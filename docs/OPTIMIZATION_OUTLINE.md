# 系统优化文档 生成大纲

## 角色定位
你是一名首席优化架构师，基于系统监控数据、压测基线与性能告警，制定结构化、可量化、可回滚的系统优化方案。

## 目标读者
- 架构师：关注瓶颈分析、方案设计、架构演进
- SRE/运维：关注实施步骤、回滚预案、监控验证
- 开发工程师：关注优化项详情、代码变更、性能调优
- 产品/财务：关注 ROI、成本优化、收益评估

## 章节结构

### 第1章 现状分析
**目的**：建立优化前的"体检报告"作为对照基线。
**要点**：
- 系统画像（架构概述、业务规模、部署形态、关键路径）
- 基线指标（性能 P99/吞吐、可用性 SLA、资源 CPU/内存利用率、单位成本，对比行业基线与差距）
- 监控数据分析（近 30/90 天趋势、热点时段、异常事件）
- 问题清单（编号/问题/类别/严重度/影响范围/数据来源）
- 利益相关方矩阵
- 优化范围（In-Scope / Out-of-Scope）
- 术语与缩略语（SLI、SLO、USE、RED、RT、QPS）
- 参考文档（系统架构文档、监控基线报告、压测基线报告）

### 第2章 瓶颈定位与分析
**目的**：用方法论定位瓶颈、根因与热点。
**要点**：
- 分析方法论（USE 资源层、RED 请求层、黄金信号、火焰图、链路追踪）
- 瓶颈清单（编号/瓶颈/层级/位置/证据/影响指标/严重度）
- 根因分析（每个 P0/P1 瓶颈做 5 Whys 或鱼骨图）
- 热点定位（代码热点函数、SQL 慢查询、网络高延迟、资源高负载节点）
- 容量与水位分析（当前/峰值/容量上限/预计耗尽时间/风险）
**示例/模板**：
```markdown
### BN-001 <瓶颈名>
**现象**：<观察>
**5 Whys**：
1. 为什么？→ <答案>
5. 为什么？→ <根因>
**根因**：<根因>
**关联瓶颈**：BN-XXX
```

### 第3章 优化目标
**目的**：用 SMART 原则设定量化与非量化目标。
**要点**：
- 目标设定原则（SMART、北极星指标如 Cost per Request 下降 30%、不破坏现有 SLA）
- 量化指标目标（编号/维度/当前值/目标值/提升幅度/验证方式/截止日期）
- 非量化目标（可维护性、技术债务、监控覆盖、知识沉淀）
- 目标优先级矩阵（业务价值×实现成本×风险）
- 不在优化范围内（明确不做什么，避免范围蔓延）

### 第4章 优化方案设计
**目的**：按 9 个技术维度分层给出可落地的优化项（编号 `OPT-<层级>-NNN`）。
**要点**：
- 方案分层总览（应用与并发、数据库、缓存与MQ、网关与韧性、安全、架构与一致性、可观测性、部署、成本，含方案数/收益/难度/责任人）
- 应用与并发优化（线程模型、线程池调优、异步化改造、协程化；API 协议/序列化/批量化/分页/连接复用/字段裁剪/预计算）
- 数据库优化（连接池、ORM、读写分离、分片；事务隔离/拆分/最终一致/锁优化；慢查询/索引/执行计划/分页/表结构；分库分表/分区/冷热分离/HTAP/主从延迟）
- 缓存与消息队列优化（多级缓存、命中率、失效策略、防穿透/雪崩/击穿、大Key/热Key；MQ 选型、分区、顺序、幂等、重试、堆积、事务消息）
- 网关与韧性优化（限流算法、多维度限流、熔断、降级、路由转发、重试、超时、背压、BFF、灰度路由）
- 安全优化（加密性能、JWT、WAF、限权、密钥轮转、防爬、脱敏、旁路检查）
- 架构与一致性优化（一致性级别、分布式事务、幂等、对账、双写；故障域、隔离、优雅上下线、无损发布、多活；CQRS、计算存储分离、微服务、事件驱动、Serverless）
- 可观测性与容量优化（指标体系、链路追踪、结构化日志、Profiling、容量水位、容量预测、告警降噪、混沌工程）
- 部署与自动化优化（启动加速、弹性伸缩、预热、配置动态化、IaC、流水线、灰度发布、边缘计算）
- 成本优化 FinOps（预留实例、Spot、右尺寸、闲置回收、存储分级、网络成本、单位经济成本、自动关停）
- AI 时代专属优化（如适用：模型推理、Token 成本、向量检索、RAG、Embedding 缓存、流式响应）
- 方案对比与选型（多候选方案对比表）

### 第5章 实施步骤
**目的**：制定分阶段、灰度化、可回滚的实施路线图。
**要点**：
- 实施原则（先量化后优化、先灰度后全量、先无风险后有风险、单次变更最小化、可观测先行）
- 实施路线图（P1 快速收益 1-2 周 / P2 中等收益 3-6 周 / P3 深度优化 7-12 周）
- 灰度策略（流量百分比 1%→10%→50%→100%，观察时长，升级条件）
- 变更窗口（可变更/不可变更窗口、紧急变更流程）
- 实施清单 Checklist（基线已采集、监控已配置、灰度已评审、回滚已就绪、通知已发送、验证脚本已准备）
- 操作步骤详述模板（类型/风险等级/耗时/执行窗口/执行人/审核人/前置准备/执行步骤/验证步骤/回滚步骤）

### 第6章 风险评估
**目的**：登记风险类别、监控指标与应急预案。
**要点**：
- 风险登记（编号/风险/类别/概率/影响/风险值/缓解措施/责任人/状态）
- 风险类别（性能、可用性、数据、安全、依赖、容量）
- 风险监控（错误率/P99 延迟/资源利用率阈值与自动动作如自动回滚/暂停灰度/扩容）
- 风险应急预案（雪崩、数据丢失等场景触发条件/应急动作/责任人）

### 第7章 验证方法
**目的**：通过对照基线、压测、A/B 与长期观察验证优化效果。
**要点**：
- 验证策略（对照基线、压测先行、线上 A/B、长期观察 7/30 天复测）
- 压测方案（编号/场景/工具/并发/时长/通过标准）
- 验证指标（指标/优化前/优化后/目标/达成 ✅/❌）
- 回归测试（功能、性能、兼容性回归）
- 长期观察（性能指标 30 天/稳定性 30 天/成本 1 账期）

### 第8章 回滚预案
**目的**：定义回滚触发条件、策略与演练机制。
**要点**：
- 回滚触发条件（错误率飙升 >5% 持续 5min、P99 劣化 >基线 2x 持续 10min、业务投诉、数据异常，自动/手动）
- 回滚策略（代码 Git Revert、配置历史版本、数据备份恢复/闪回、流量 DNS/网关切流）
- 回滚步骤模板（触发条件/决策人/执行人/耗时/步骤/验证清单）
- 数据回滚（备份策略全量+增量+日志、恢复方式、恢复演练频率）
- 流量切换（DNS/网关/LB 切换工具、RTO、影响）
- 回滚演练（季度频率、记录位置、改进措施跟踪）

### 第9章 收益评估与 ROI
**目的**：量化业务/技术/成本收益并计算 ROI。
**要点**：
- 业务收益（用户体验 P99、业务转化率、客户满意度 NPS）
- 技术收益（系统容量 QPS、可用性 SLA、可观测性指标覆盖）
- 成本收益（计算/存储/网络/人力成本优化前后对比，合计节省 ¥/月）
- ROI 计算（投入成本人力+工具+资源、年化收益、回收周期、3 年 ROI）
- 无形收益（技术能力提升、团队认知升级、技术债务清理、知识沉淀）

### 第10章 持续优化与治理
**目的**：建立复盘机制、债务登记与下一轮迭代。
**要点**：
- 优化看板（位置与关键指标，含趋势图）
- 复盘机制（版本后/季度频率，回顾/分析/改进流程）
- 技术债务登记（编号/债务/影响/偿还计划/责任人/状态）
- 下一轮迭代（候选项/预期收益/难度/优先级）
- 持续优化机制（容量季度评审、成本月度评审、性能月度评审、架构季度治理）
- 知识沉淀（优化手册、经验案例库、培训资料）

### 第11章 附录
**目的**：提供监控基线、压测报告、变更记录与追踪矩阵。
**要点**：
- 监控基线数据（优化前关键指标完整数据，含趋势图）
- 压测报告（完整报告链接，含场景/数据/结果）
- 变更记录（日期/优化项/执行人/变更内容/验证结果/备注）
- 优化项追踪矩阵（优化项/关联瓶颈/关联目标/实施状态/验证结果/收益）
- 参考资料（《System Performance Analysis》Brendan Gregg、《SRE》Google、《数据密集型应用系统设计》、USE Method、RED Method）

## 写作规范
- 编号约定：OPT-NNN（优化项）、R-NNN（风险）、MET-NNN（监控指标）、PERF-NNN（压测场景）、BN-NNN（瓶颈）、GOAL-NNN（目标）
- 优化项必须给出预期收益（量化）和风险评估
- 所有优化指标必须基于监控/压测真实数据，避免拍脑袋
- 优化方案不得破坏安全边界，性能优化项需经安全架构师评审
- 实施遵循"先量化后优化、先灰度后全量"原则
- 每个优化项必须配套回滚方案
