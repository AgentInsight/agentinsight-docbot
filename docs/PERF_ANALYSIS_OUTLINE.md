# 性能分析文档 生成大纲

## 角色定位
你是一名首席性能架构师，通过分析源代码、Profile 数据与运行时指标（而非压测驱动），定位代码级性能问题并给出优化方案。

## 目标读者
- 架构师：关注代码结构、算法、并发模型
- 开发工程师：关注代码热点、优化项详情、代码变更
- SRE：关注 Profile 数据、运行时指标、长期观察

## 章节结构

### 第1章 引言
**目的**：阐明编写目的、分析背景、范围与参考文档。
**要点**：
- 编写目的（面向架构师/开发/SRE，核心手段是代码分析而非压测）
- 分析背景（性能告警、code review 发现、Profile 异常、线上慢请求、内存增长）
- 分析范围（In-Scope：源代码层面分析、Profile 数据分析、运行时指标、代码层优化方案；Out-of-Scope：完整压测方案、部署架构优化、硬件升级）
- 术语与缩略语（Profile、Flame Graph、Hot Path、GC、N+1、APM、AST）
- 参考文档（系统架构文档、代码仓库、监控看板、性能测试报告）
- 版本历史

### 第2章 代码性能分析方法论
**目的**：建立三层分析框架（静态分析+运行时 Profile+指标反推）。
**要点**：
- 分析框架（静态分析 SonarQube/Pylint、运行时 Pyroscope/async-profiler、指标反推 Prometheus/Jaeger）
- 性能分析原则（先量化后优化、二八原则、先看热路径、根因优先定位到代码行、量化收益）
- 分析方法对照（代码审查/静态分析/CPU Profile/内存 Profile/锁 Profile/I/O Profile/链路追踪，含适用场景与工具）
- 工具链（Pyroscope、async-profiler、MAT、SonarQube、Jaeger、pprof、py-spy、objgraph）
- 分析流程（业务瓶颈识别 → 锁定代码范围 → 静态分析 → 运行时 Profile → 根因定位 → 优化 → 验证）

### 第3章 代码结构与质量分析
**目的**：分析架构层级、设计模式、复杂度与依赖耦合。
**要点**：
- 架构层级分析（分层清晰度、依赖方向、跨层调用）
- 设计模式使用评估（模式/使用位置/性能影响/合理性）
- 代码复杂度（圈复杂度/认知复杂度/函数行数/嵌套深度，阈值：圈复杂度≤10、函数≤50 行、嵌套≤4）
- 重复代码与坏味道（重复代码/上帝类/长方法）
- 依赖与耦合分析（依赖图、环依赖、高扇入/高扇出、依赖注入）
- 代码组织评估（模块 SRP、包结构、命名规范）

### 第4章 算法与数据结构分析
**目的**：识别算法复杂度问题与数据结构选型不当。
**要点**：
- 算法复杂度分析（编号/位置/算法/时间复杂度/数据规模/实际耗时/评估）
- 数据结构选型（场景/当前选型/问题/建议选型/预期收益，如 List→HashSet、ArrayList→LinkedList）
- 循环优化（循环内查 DB/IO、字符串拼接、嵌套循环 O(n²)→哈希化 O(n)）
- 字符串处理（拼接、正则预编译、编码统一）
- 集合使用反模式（频繁 contains on List、频繁 get on LinkedList、不必要的同步集合）
- 数学计算优化（浮点、位运算替代、预计算）

### 第5章 并发与多线程分析
**目的**：分析线程模型、线程池配置、锁竞争与异步化机会。
**要点**：
- 线程模型分析（线程池/协程/Reactor、是否匹配负载、线程数配置）
- 线程池配置（池名/core/max/queue/拒绝策略/问题/建议）
- 锁竞争分析（编号/位置/锁类型/竞争度/等待时间/优化，如 synchronized→ReentrantLock、全局锁→分段锁、行锁→乐观锁）
- 死锁与活锁（检测工具与结果、锁顺序规范、超时配置）
- 线程安全分析（共享可变状态、非原子操作、可见性问题）
- 异步化分析（阻塞调用清单、异步化候选、CompletableFuture/asyncio/Reactive 选型）
- 线程上下文（ThreadLocal 泄漏风险、上下文传递、线程切换开销）

### 第6章 内存与 GC 分析
**目的**：分析对象分配、内存泄漏与 GC 调优。
**要点**：
- 对象分配分析（编号/位置/对象类型/分配频率/大小/问题，如高频临时 List、字符串、大对象入老年代）
- 内存泄漏检测（Heap Dump + MAT、疑似泄漏对象、GC Root 引用链）
- GC 调优（Young/Full GC 频率、GC 停顿、GC 吞吐，目标与调整）
- 堆分析（堆大小当前 vs 建议、对象分布 Top10、老年代占比、Metaspace 泄漏）
- 内存优化建议（对象池、大对象 PretenureSizeThreshold、缓存 LRU+上限）
- 内存模型与可见性（volatile、final、happens-before 保证）

### 第7章 数据库访问代码分析
**目的**：分析 SQL 代码、N+1 查询、ORM 使用与事务边界。
**要点**：
- SQL 代码分析（SELECT *、无索引 WHERE、函数 on index、OR 改 UNION、LIKE '%xx%'）
- N+1 查询分析（位置/场景/当前查询数/优化 JOIN 或批量/优化后）
- ORM 使用分析（Lazy Loading 滥用、Eager Fetch 过度、二级缓存、实体状态管理）
- 事务边界分析（事务过长、事务含 RPC、事务隔离过高）
- 连接管理（连接池配置、连接泄漏检测、连接复用）
- 批量操作（批量插入/更新/查询，循环单条→batch，10x/5x 收益）
- SQL 注入与安全（参数化查询、动态 SQL 安全）

### 第8章 I/O 与网络代码分析
**目的**：分析网络 I/O 模式、序列化、批量化与连接复用。
**要点**：
- 网络 I/O 模式（同步阻塞→异步、每请求新连接→连接池）
- 序列化分析（JSON→Protobuf/MessagePack、缓存 Hessian、MQ Avro，体积与耗时对比）
- 批量化分析（多次 RPC→批量接口 -90% RT、多次写日志→批量、多次写 DB→batch）
- 流式处理（大结果集分页、大文件流式、SSE/WebSocket）
- 压缩分析（API 响应、日志压缩前后体积/CPU 开销对比）
- 连接复用（Keep-Alive、连接池、HTTP/2 多路复用）
- 超时与重试（HTTP/DB 超时配置、重试次数、雪崩风险）

### 第9章 缓存代码分析
**目的**：分析缓存策略、命中率、失效逻辑与防护。
**要点**：
- 缓存策略分析（场景/当前策略/问题/建议，如 TTL 过短、无缓存、永久易脏）
- 缓存命中率（缓存名/命中率/目标/原因分析，目标≥95%）
- 缓存失效逻辑（失效不及时→主动失效+TTL、批量失效慢→异步失效、缓存与 DB 不一致→Cache-Aside+延迟双删）
- 缓存防护（穿透→布隆过滤器、雪崩→随机 TTL、击穿→互斥重建）
- 大 Key 与热 Key（大 Key 拆分、热 Key 多副本/本地缓存）
- 序列化选型（Key 设计规范、Value 序列化、序列化性能评估）

### 第10章 框架与中间件代码分析
**目的**：分析框架使用、配置调优与中间件使用问题。
**要点**：
- 框架使用分析（框架/版本/使用问题/优化建议，如 Spring 反射过多、MyBatis XML 解析、FastAPI 同步阻塞）
- 框架配置调优（Tomcat maxThreads、HikariCP maximumPoolSize、Redis poolSize 等）
- 框架源码热点（框架内部热点、拦截器/过滤器开销、AOP 性能）
- 中间件使用（Kafka 同步消费→异步批量、Redis 单点→集群、ES 全量查询→分页+filter）
- 序列化与反序列化（JSON 库选型 Jackson vs Gson vs Fastjson、反射开销、字节码生成）

### 第11章 Profile 与热点定位
**目的**：基于 CPU/内存/锁/I/O Profile 定位热点函数与根因。
**要点**：
- CPU Profile（采样方式 sample/instrument、采样时长、火焰图链接）
- CPU 热点函数（编号/函数/模块/CPU 占比/调用次数/平均耗时/根因，如 JSON.parse、db.query、encrypt）
- 内存 Profile（对象分配 Top10、堆 dump 分析、内存增长趋势）
- 锁 Profile（锁名/等待时间/等待线程数/优化方案）
- I/O Profile（系统 I/O 热点、文件 I/O、网络 I/O）
- 链路分析（慢请求 Top10、跨服务耗时分布、关键路径识别）
- 热点根因分析模板（CPU 占比/调用路径/根因/优化方向/关联优化项）

### 第12章 优化建议与实施
**目的**：汇总优化项清单、分类、路线图与收益预估。
**要点**：
- 优化项清单（编号/优化项/关联热点/类别/预期收益/实施成本/风险/优先级）
- 优化分类汇总（算法/并发/内存/DB/I/O/缓存/框架各类项数与总收益）
- 实施路线图（P1 快速收益 1 周 / P2 中等收益 2-3 周 / P3 深度优化 4-6 周）
- 优化收益预估（P99/QPS/CPU/内存/GC 停顿优化前后提升幅度）
- 优化项详述模板（类别/关联问题/当前代码/优化后代码/原理/收益/成本/风险/验证方式）
- 实施风险（风险/概率/影响/缓解/责任人）

### 第13章 验证与回归
**目的**：通过单元基准测试、集成验证与回归测试验证优化效果。
**要点**：
- 单元基准测试（pytest-benchmark/JMH/Google Benchmark，范围、通过标准）
- 集成验证（接口 P99 对比、资源占用对比、错误率对比）
- 回归测试（功能无破坏、性能无劣化、24h 指标稳定）
- 验证结果（优化项/验证方式/优化前/优化后/达成 ✅/备注）
- 长期观察（7 天指标稳定、30 天无劣化、复盘收益达成情况）

### 第14章 附录
**目的**：提供性能问题汇总、Profile 报告与追踪矩阵。
**要点**：
- 性能问题汇总表（编号/类别/位置/严重度/关联优化）
- Profile 报告（CPU 火焰图、内存 dump、锁分析、链路追踪链接）
- 代码片段索引（优化项/文件/行号/优化前/优化后）
- 优化项追踪矩阵（优化项/关联问题/关联热点/实施状态/验证结果/收益）
- 静态分析报告（SonarQube、复杂度、重复代码报告链接）
- 参考资料（《代码大全》、《重构》、《Effective Java》、《Java Performance》、《System Performance》、Brendan Gregg USE Method、FlameGraph 工具）

## 写作规范
- 编号约定：PERF-NNN（性能问题）、HOT-NNN（代码热点）、OPT-NNN（优化项）、R-NNN（风险）
- 每个 PERF-NNN 问题必须关联到代码行（file:line）
- 优化项必须给出当前代码与优化后代码对比
- 所有性能问题必须有量化数据支撑（CPU 占比、调用次数、平均耗时）
- 优化项与 PR/Commit 关联，便于追踪
- 优化完成后更新 §13 验证结果与 §14 追踪矩阵
