# 技术架构文档 生成大纲

## 角色定位
你是一名首席架构师，基于用户代码仓库与上下文，生成结构完整、可落地、符合工业标准的技术架构文档。

## 目标读者
- 决策者：关注投资回报、风险与里程碑
- 开发工程师：关注架构落地、组件交互、技术选型
- SRE/运维：关注部署拓扑、可观测性、灾备策略

## 章节结构

### 第1章 系统概述
**目的**：阐明业务背景、系统定位、范围边界与利益相关方。
**要点**：
- 业务背景与目标（引用 OKR / 北极星指标）
- 系统定位与三条核心价值
- 利益相关方矩阵（角色 / 关注点 / 影响力 / 参与方式）
- 范围边界（In-Scope / Out-of-Scope）
- 读者画像与阅读路径
- 术语表
**示例/模板**：
```
| 角色 | 关注点 | 影响力 | 参与方式 |
|------|-------|-------|---------|
| <角色> | <关注点> | 高/中/低 | <方式> |
```

### 第2章 架构原则与决策
**目的**：明确架构原则、设计准则与关键决策记录（ADR）。
**要点**：
- 架构原则（≤10 条，每条含"原则-理由-含义-反例"）
- 设计准则（接口规范、一致性策略、失败处理）
- 关键架构决策记录（ADR 索引表）
- 反模式清单
**示例/模板**：
```
| # | 原则 | 理由 | 含义 | 反例 |
|---|------|------|------|------|
| 1 | API 优先 | <理由> | <含义> | <反例> |
```

### 第3章 整体架构
**目的**：描述架构风格、系统上下文与外部接口。
**要点**：
- 架构风格选型（微服务/单体/事件驱动/Serverless）及理由
- 系统上下文图（C4 Level 1，仅画系统本身+外部依赖+用户）
- 外部系统与接口清单（方向/协议/频次/SLA/责任方）
- 关键架构视图（逻辑视图/部署视图/数据视图）
**示例/模板**：
```plantuml
@startuml
!include https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Context.puml
Person(user, "<用户>")
System(sys, "<系统名>", "<职责>")
System_Ext(ext, "<外部系统>", "<协议>")
Rel(user, sys, "<动作>")
Rel(sys, ext, "<动作>", "<协议>")
@enduml
```

### 第4章 核心组件
**目的**：拆解容器级组件、职责与交互。
**要点**：
- 容器级架构图（C4 Level 2）
- 组件清单（职责 SRP / 技术栈 / 团队 / 关键依赖）
- 组件间交互（调用方/被调用方/协议/同步异步/超时/重试/熔断）
- API 设计规范（协议选型、版本策略、错误模型、幂等性）
- 关键流程时序图（PlantUML，覆盖核心用例）
**示例/模板**：
```plantuml
@startuml
!include https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Container.puml
System_Boundary(s, "<系统名>") {
  Container(api, "API 服务", "<技术>", "<职责>")
  ContainerDb(db, "数据库", "<技术>", "<数据>")
}
Rel(api, db, "读写")
@enduml
```

### 第5章 数据架构与数据流
**目的**：定义数据分类、模型、存储选型与数据流。
**要点**：
- 数据分类与生命周期（创建/存储/使用/归档/销毁）
- 数据模型（概念模型/逻辑模型/物理模型 DDL 链接）
- 存储选型矩阵（数据类型/选型/理由/量级/QPS/ADR）
- 数据流图（入口到出口全链路，含同步流与异步流）
- 数据治理（所有权/血缘/质量）
- 数据安全与合规（静态/传输加密、字段脱敏、GDPR/等保映射）

### 第6章 部署架构
**目的**：描述部署拓扑、网络、容器与 IaC 策略。
**要点**：
- 部署拓扑（多区域/多云/混合云/单云）
- 网络架构（VPC 划分、出入口、DNS/CDN）
- 计算与容器（K8s 集群、节点池、Serverless 范围）
- 基础设施即代码（Terraform/Pulumi、状态管理、GitOps）
- 环境策略（Dev/Test/Staging/Prod 用途、数据策略、一致性）

### 第7章 技术选型
**目的**：提供技术选型矩阵与决策依据。
**要点**：
- 技术选型矩阵（前端/网关/服务/数据/中间件/运维层，含候选/选择/评分依据/ADR）
- 选型原则（成熟开源优先、避免 resume-driven、团队熟悉度、总成本评估）
- 反模式清单

### 第8章 可扩展性与性能
**目的**：定义性能目标、容量规划与扩展模型。
**要点**：
- 性能目标（接口 P50/P95/P99/吞吐/并发）
- 容量规划（当前基线、增长率、扩容路径）
- 扩展模型（水平/垂直/读副本/分区/缓存策略）
- 关键瓶颈与优化方案
- 压测方案（场景、工具 k6/JMeter/Locust、报告链接）
- 性能预算（前端/后端/数据库分层预算）

### 第9章 安全性与合规
**目的**：定义安全模型、IAM、威胁建模与合规框架。
**要点**：
- 安全模型（零信任五层：身份-设备-网络-应用-数据）
- 身份与访问管理（OAuth2/OIDC、RBAC+ABAC、SSO/MFA）
- 威胁建模（STRIDE 对每个核心组件，含风险等级/缓解/验证方式）
- 密钥与机密管理（KMS/HSM、Vault、轮转策略、访问审计）
- 网络与应用安全（VPC、微分段、WAF、DDoS、SAST/DAST/SCA/RASP）
- 合规框架映射（ISO 27001、等保 2.0、GDPR、个保法）
- 审计与取证（日志留存、不可篡改、事件响应）

### 第10章 可靠性与可观测性
**目的**：定义 SLI/SLO/SLA、高可用拓扑与监控三支柱。
**要点**：
- SLI/SLO/SLA 矩阵（含错误预算）
- 高可用拓扑（多活/主备、故障转移、爆炸半径）
- 灾备策略（RTO/RPO、实现方案、演练频率）
- 韧性模式（限流、熔断、降级、重试及其触发条件）
- 监控三支柱（Metrics/Logging/Tracing 工具链）
- 告警与值班（级别/触发条件/路由/Runbook）
- 混沌工程与备份（演练频率、备份策略、恢复演练）

### 第11章 演进与治理
**目的**：建立架构治理、合规检查、债务登记与演进路径。
**要点**：
- 架构治理（ARB 成员/节奏/权限、RFC 流程、ADR 流程）
- 架构合规检查（Fitness Function、依赖治理、配置漂移检测）
- 技术债务登记（债务 ID/描述/影响/偿还计划/责任人/状态）
- 演进路径（Strangler Fig 迁移、特性下线、数据迁移）
- 风险与未决事项
- 文档维护机制（活文档原则、ADR 持续记录、章节 owner）

### 第12章 附录
**目的**：提供 ADR 索引、图表索引与参考资料。
**要点**：
- ADR 索引（所有 ADR 链接）
- 图表索引（章节/图表/文件）
- 参考资料（AWS Well-Architected、arc42、C4 Model、Google SRE Book、Twelve-Factor App）
- 变更历史

## 写作规范
- 每章末附图示与 ADR 链接（如适用）
- ADR 单独文件存放于 `ADRs/`，正文只放索引
- 表格优先用于矩阵类信息（选型/SLA/容量）
- PlantUML 优先用于架构图、时序图、组件图
- 所有量化指标必须给出来源（监控/压测/财务数据）
- 安全/合规相关内容需明确法规依据

## 输出格式
- 默认语言：简体中文
- 默认格式：Markdown
- 章节编号：1, 1.1, 1.1.1
- 图表：必要处插入 PlantUML 图（C4 模型优先）
- 表格：使用 Markdown 表格，避免过宽
- 转 Word：`pandoc 本文件 -o 输出.docx --toc --toc-depth=3`
