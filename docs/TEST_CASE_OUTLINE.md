# 测试用例文档 生成大纲

## 角色定位
你是一名测试架构师，基于需求文档与设计文档，生成结构化、可自动化解析、覆盖全生命周期的测试用例文档。

## 目标读者
- 测试工程师：关注用例设计、缺陷管理、执行计划
- 开发工程师：关注用例覆盖、自动化集成
- PM/SRE：关注质量门禁、风险评估
- 法务：关注数据合规与脱敏

## 章节结构

### 第1章 引言
**目的**：阐明编写目的、项目背景、文档范围与参考文档。
**要点**：
- 编写目的（面向测试/开发/PM/SRE/法务，与测试计划的边界）
- 项目背景（系统简介、版本目标、本次测试覆盖的业务背景）
- 文档范围（In-Scope / Out-of-Scope）
- 术语与缩略语（SIT、UAT、RTM、DoD 等）
- 参考文档（PRD、HLD、接口规范）
- 版本历史

### 第2章 测试范围
**目的**：明确测试模块、类型覆盖与排除项。
**要点**：
- 范围矩阵（模块/功能点/是否测试/测试类型/优先级/关联 FR）
- 测试类型覆盖（单元/集成/系统/性能/安全/兼容性/验收，含责任方）
- 假设与排除项（系统已部署、测试账号就绪、第三方 Mock 可用等）

### 第3章 测试策略与方法
**目的**：定义测试分层、用例设计方法与自动化策略。
**要点**：
- 测试分层（金字塔：单元 70%/集成 20%/端到端 10%，含工具/自动化率/阻断级别）
- 用例设计方法（等价类划分、边界值分析、决策表、状态迁移、错误猜测、因果图、正交试验）
- 自动化策略（范围/框架/维护/触发/报告）
- 探索式测试（时间盒、主题、记录方式）
- 回归策略（触发条件/范围/优先级）

### 第4章 测试环境
**目的**：定义环境清单、硬件软件配置与数据隔离。
**要点**：
- 环境清单（Dev/Test/Staging/Perf/Prod 用途/数据/隔离/责任方）
- 硬件与软件配置（CPU/内存/数据库版本/数量）
- 网络与依赖（VPC/带宽/延迟模拟、第三方 Mock、外部服务桩）
- 数据隔离与回收（按租户/测试账号隔离、每日清理、状态重置脚本）
- 环境治理（申请流程、配置漂移检测、监控）

### 第5章 测试用例设计
**目的**：定义用例编号规则、覆盖率目标与用例模板。
**要点**：
- 用例编号规则（TC-<模块缩写>-NNN，如 TC-USER-001）
- 覆盖率目标（需求覆盖率/代码覆盖率/路径覆盖率）
- 模块用例清单（模块/用例数/P0/P1/P2/自动化/责任人）
- 测试用例模板（优先级/类型/关联需求/前置条件/测试步骤/期望结果/后置条件/测试数据）
- 用例设计示例
**示例/模板**：
```markdown
### TC-<模块>-NNN <用例标题>
- **优先级**：P0 / P1 / P2
- **类型**：功能 / 接口 / 性能 / 安全 / 兼容
- **关联需求**：FR-001
- **前置条件**：
  1. <条件>
- **测试步骤**：
  1. <步骤描述> → 期望：<期望结果>
- **测试数据**：<引用 §6 数据 ID>
```

### 第6章 测试数据
**目的**：定义数据清单、生成策略与脱敏规范。
**要点**：
- 数据清单（数据 ID/名称/类型/用途/关联用例）
- 数据生成策略（真实数据脱敏、Faker/工厂模式 Fixture、边界数据、异常数据）
- 数据脱敏（手机号/身份证/银行卡等敏感字段脱敏方式）
- 数据管理与回收（存储/版本/隔离/回收时机）
- 数据合规（来源合法性、留存期、销毁方式）

### 第7章 进入/退出条件与质量门禁
**目的**：定义 DoR/DoD 与各阶段质量门禁。
**要点**：
- 进入条件 DoR（需求已评审、设计已冻结、环境就绪、数据已准备、开发自测完成）
- 退出条件 DoD（用例执行率 100%、通过率≥98%、P0/P1 缺陷 0、P2 缺陷≤5、性能达标、安全扫描无严重漏洞、回归通过）
- 质量门禁（PR 合入/CI/预发/发布各阶段指标与阻断动作）
- 缓冲与豁免（RFC+审批流程、缓冲期、责任人）

### 第8章 缺陷管理
**目的**：定义缺陷生命周期、分级与报告模板。
**要点**：
- 缺陷生命周期（New → Assigned → Fixing → Fixed → Ready for Test → Verified → Closed / Reopened）
- 严重度分级（P0 致命 4h / P1 严重 24h / P2 一般 3 工作日 / P3 轻微版本内 / P4 建议）
- 优先级矩阵（严重度×优先级，确定修复 SLA）
- 缺陷报告模板（严重度/优先级/环境/复现步骤/期望/实际/附件/关联用例）
- 缺陷统计与报告（日报/周报/版本报告/看板）
- 根因分析（5 Whys / 鱼骨图，P0/P1 必做）
**示例/模板**：
```markdown
### BUG-NNNN <缺陷标题>
- **严重度**：P0/P1/P2/P3
- **优先级**：高/中/低
- **环境**：<环境名>
- **复现步骤**：
  1. <步骤>
- **期望结果**：<期望>
- **实际结果**：<实际>
- **关联用例**：TC-XXX
```

### 第9章 测试计划与资源
**目的**：定义里程碑、人力资源与工具平台。
**要点**：
- 测试里程碑（用例评审完成/第一轮测试/回归测试/UAT/上线，含日期/范围/责任人）
- 人力资源（测试经理/功能/自动化/性能/安全，含人数/工作量/责任范围）
- 工具与平台（用例管理 TestRail/Zephyr、缺陷管理 Jira/Redmine、自动化 Pytest/Playwright、性能 k6/Locust、安全 OWASP ZAP/Burp、CI/CD）
- 培训与沟通（培训计划、日站会/周例会/评审会、文档库）

### 第10章 风险评估与应急
**目的**：登记测试风险、监控指标与应急预案。
**要点**：
- 风险登记（环境不稳定、第三方延期、覆盖率不足等，含概率/影响/缓解/应急/责任人）
- 风险监控（环境可用率、用例执行率、缺陷修复率，含阈值与告警）
- 应急预案（环境故障/严重缺陷/数据丢失，触发条件/应急动作/责任人）
- 回退方案（回退触发条件、回退步骤、通知流程）

### 第11章 附录
**目的**：提供术语表、模块用例详述、追踪矩阵与报告模板。
**要点**：
- 术语表完整版（与 §1.4 同步）
- 模块用例详述（每模块按 §5.4 模板展开）
- 需求-用例-缺陷追踪矩阵 RTM（需求/用户故事/用例/测试结果/缺陷/状态）
- 测试报告模板（测试周期/用例执行/缺陷统计/质量结论/遗留风险）
- 检查清单 Checklist（用例评审/环境就绪/数据准备/自动化集成 CI/缺陷关闭/报告输出/上线评审）
- 参考资料（ISTQB、IEEE 829、ISO/IEC/IEEE 29119、《Google 软件测试之道》、《敏捷软件测试》）

## 写作规范
- 编号约定：TC-<模块缩写>-NNN（如 TC-USER-001）、TS-NNN（场景）、BUG-NNNN（缺陷）
- 所有用例必须按统一模板编写，便于自动化解析
- 测试步骤必须明确"步骤→期望结果"对应关系
- 缺陷必须关联到具体用例 TC-XXX
- 维护 RTM 实现需求→用例→缺陷端到端追踪
- 自动化用例必须纳入 CI 流水线

## 输出格式
- 默认语言：简体中文
- 默认格式：Markdown
- 章节编号：1, 1.1, 1.1.1
- 图表：流程图、状态机图（用 PlantUML 或代码块表示）
- 表格：使用 Markdown 表格
- 转 Word：`pandoc 本文件 -o 输出.docx --toc --toc-depth=3`
